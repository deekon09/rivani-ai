What image compression actually changes

Image compression reduces the number of bytes required to store a picture. Lossy formats such as JPEG, WebP and AVIF can discard some visual information to save space, while PNG is normally lossless and therefore behaves differently. The best result is not simply the smallest file; it is the smallest file that still looks right for its job.

RIVANI Smart Image Compressor is designed around that trade-off. Easy mode handles normal sharing, Exact Size targets a specific KB or MB ceiling, and Precision mode exposes format, quality and dimension controls.

Compress an image to 20 KB, 50 KB, 100 KB or 200 KB

Exact byte limits are common on application forms, profile uploads and document portals. A single quality percentage cannot guarantee a final size because two images with the same dimensions can contain very different detail.

RIVANI therefore uses repeated encoding passes. It searches for the highest useful quality that fits the target. If a very small target cannot be reached with quality alone, Strict Target can reduce dimensions. Quality-first is more conservative: it can deliberately stay above the requested size rather than cross the visual floor.

Exact size is a constraint, not magic.

A detailed 12-megapixel photo cannot always become 20 KB and still retain the same resolution and visible detail. When the target is too aggressive, either quality, dimensions or both must change.

JPG, WebP, PNG and AVIF: which should you choose?

  • JPEG: broad compatibility and predictable photo compression, but no transparency.
  • WebP: efficient for many photos and can retain transparency.
  • PNG: lossless and useful for logos, graphics and alpha, but can remain large.
  • AVIF: can be very efficient when the browser supports encoding it; RIVANI tests support before offering it as a race candidate.

Smart Format Race can test compatible encoders and keep the smallest candidate that satisfies the current guard rules. Transparency Guard removes JPEG from the race when alpha pixels are detected.

Visual Quality Guard and Text & Logo Guard

Visual Quality Guard decodes the compressed result and compares it with the resized source. RIVANI reports a heuristic similarity estimate based on pixel error and edge retention. It is a useful warning signal, not a laboratory or perceptual-quality certification.

Text & Logo Guard looks for dense fine-edge content. Screenshots, posters, UI captures and logos often need a higher quality floor than smooth photography, so the compressor can become more conservative when that kind of structure dominates.

Compression Artifact Map

The Artifact Map highlights where the decoded result differs most from the resized source. It is useful for spotting blockiness, ringing, damaged small text or gradient banding that may not be obvious at first glance. Review important document images at 100% before using them.

Batch compression with consistency

Batch mode accepts multiple images and applies one workflow across them. When Batch Consistency is enabled, Smart Format Race attempts to keep the same winning format across the batch when that format remains compatible. This is useful for product galleries and web assets that should behave predictably.

Every image still receives its own size and quality pass because visual complexity is different from file to file.

Website Pack export

Website Pack generates responsive image widths plus modern WebP output, a JPEG fallback and AVIF when the current browser can encode it. The ZIP also includes a ready-to-edit <picture> snippet with srcset candidates. It is intended as a fast starting point for websites, not a substitute for testing your final page layout and Core Web Vitals.

Browser-side privacy and metadata

Image pixels are decoded, resized and re-encoded in the browser. RIVANI account sign-in gates processing access, but the compressor itself does not need to upload the image to a compression backend. Canvas re-encoding also strips embedded metadata by default, which can remove camera and location metadata from the exported file.

Practical limits

  • Very large images can exceed mobile memory, so RIVANI can adapt them to a device-safe working resolution.
  • PNG cannot be quality-tuned like a lossy photo format; exact tiny targets may require a modern lossy format or smaller dimensions.
  • AVIF encoding depends on browser support and may not appear in every environment.
  • A high similarity estimate does not guarantee that tiny text or legally important visual facts are unchanged. Review critical images manually.

Recommended workflow

  1. Start with Balanced Easy mode for normal sharing.
  2. Use Exact Size only when a portal requires a hard byte limit.
  3. Keep Quality Guard and Text & Logo Guard on for screenshots and documents.
  4. Open Artifact Map when the file becomes dramatically smaller.
  5. Use Website Pack when preparing responsive assets for a site.
